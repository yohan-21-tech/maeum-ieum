# 마음이음 upgrade implementation plan

Goal: Upgrade the existing Next.js teacher/parent MVP with traceable evidence, enforced human review, privacy controls, and a tested team-demo delivery.

Architecture: Preserve App Router, Prisma and existing role-specific flows. Work in a separate workspace copy; do not modify the original desktop app or its DB. Use a reviewed, versioned official-source corpus and lexical retrieval; never represent synthetic cases or similarity as legal authority/probability. Hosted DB and account credentials are external deployment prerequisites.

Tech stack: Existing Next.js 15, React 19, TypeScript, Prisma 6, Zod, Vitest. No new application dependency needed.

Spec: User request in this chat and existing README. All requested capabilities are evaluated, with deployment and live-provider limitations explicitly documented.

## Scope and ownership
- Security work: lib/auth.ts, lib/api.ts, lib/crypto.ts, API auth/settings/messages/reports/demo/students, Prisma schema, security tests. Preserve existing endpoint compatibility; add approval and ownership checks, bounded validation, consent records and scoped audit access. Database changes additive only.
- Evidence work: lib/laws.ts, lib/cbr.ts, lib/ai.ts, AI route, data/laws, new privacy helper, feedback/evaluation endpoints and tests. Validated dates, official-domain provenance, confidence explanation, redacted provider inputs, deterministic fallback and no unsupported legal claims.
- UX work: components, app dashboard/auth pages and styles only. Existing brand preserved. Show evidence provenance/date/status, mode, feedback, explicit review confirmation, privacy/audit controls, accessible dialogs and errors.
- Integration: package scripts, environment example, build settings, PostgreSQL schema generation and migrations, README, evaluation fixtures, smoke tests and distributable source ZIP excluding data/secrets/dependencies.

## Review focus
1. Cross-user report/message/feedback/audit access must fail without exposing private drafts.
2. Missing, revoked or malformed consent must prevent external AI processing.
3. Future, expired, stale or unverified sources must never be current legal authority.
4. Sharing and sending must require deliberate review; edited drafts must invalidate previous approval.
5. Production must not silently use plaintext, known demo credentials, an ephemeral local DB or weak audit behavior.

## Work sequence
- [ ] Record baseline tests/typecheck; add focused failing regression tests before nontrivial implementation.
- [ ] Security controls and approval transaction tests.
- [ ] Official evidence corpus, retrieval/date gates, privacy boundary, CBR and evaluation tests.
- [ ] Wire UI to real persisted feedback and approval APIs; keyboard/mobile checks.
- [ ] Run complete unit suite, typecheck, build, HTTP smoke tests and evaluation set.
- [ ] Independent final review, fix material findings, document remaining limitations and deployment requirements.

## Decisions
- Separate copy and fresh demo database: original source and user records remain untouched.
- No new deep-learning training: retrieval plus an optional existing model is achievable with the available MVP/data.
- Curated official snapshots with explicit validity/review deadlines, not unverified live web snippets.
- No external message sending or public publishing unless credentials and a reviewable deploy are available.
